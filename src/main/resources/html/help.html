General information

EXTRARNAS (Tool for the Analysis of RNA Structures) is a Java application designed to analyze RNA 3D structures and extract their secondary structures and base-pairing interactions. It provides a guided interface to configure and run specialized bioinformatics tools inside isolated environments, generating standardized outputs.

How to use EXTRARNAS

The typical EXTRARNAS workflow consists of the following steps:

  1. Shared Volume / Workspace Setup: select a local directory to be shared with the Docker container. This directory is used to pass input data to the analysis tools and retrieve their outputs.
  2. Add CSV Molecules List: select a CSV file containing the RNA structures to analyze. The file must contain two columns, id and chain.
    • id is the four-character PDB identifier.
    • chain is the author/PDB chain identifier (_atom_site.auth_asym_id). Do not use the mmCIF _atom_site.label_asym_id.
    • Chain identifiers are case-sensitive.
    • Use semicolons to request multiple chains, for example BB;DB.
    • Use * to process all RNA chains in the structure.

    Example:

    id chain
    4PLX A
    6QNR A
    4V5K BB;DB
    2KOC *

    The CSV file itself does not need to be stored inside the shared workspace because it is read by the EXTRARNAS host application. Local PDB files referenced by their IDs, however, must be placed in the shared workspace so that Docker-based tools can access them.

    Structures already present in the workspace preprocessed folder are restored when EXTRARNAS starts. Deleting a structure from the table also removes its generated PDB and mmCIF files from preprocessed.

  3. Tool Selection: choose the structural analysis tool to run.
  4. Structure Analysis Level:
    • Secondary Structure: analyzes and extracts canonical cis Watson–Crick base pairs.
    • Extended Secondary Structure: extracts all Leontis–Westhof base-pair types.
  5. Output Format:
    • BPSEQ: standard output reporting only canonical cis Watson–Crick base pairs (A-U, G-C and G-U).
    • Extended BPSEQ: an extended format in which the third column corresponds to canonical cis Watson–Crick pairs, while the remaining columns encode the other Leontis–Westhof base-pair types.
  6. Run: after selecting the tool, analysis level and output format, click RUN to execute the analysis.

Extended BPSEQ format

The Extended BPSEQ format includes the following columns:

id nt cWW tWW cWH tWH cWS tWS cHH tHH cHS tHS cSS tSS

The role of Docker

EXTRARNAS uses Docker containers to run its underlying analysis tools in isolated and reproducible environments.

The standard analysis environment is provided by the extrarnas-core image, tagged with the EXTRARNAS release. Optional tools with separate licensing requirements, such as X3DNA-DSSR, use dedicated images.

Using Docker means that:

  • you do not need to manually install complex third-party tools, compilers or specific language versions on your system;
  • executions are isolated and reproducible;
  • Docker Desktop must be installed and running before starting the analysis.

Troubleshooting

JavaFX startup problem

EXTRARNAS requires Java 21 or higher. If the application does not start because of a JavaFX error, install JavaFX 21 and launch the application specifying the JavaFX modules.

Molecules loading error

If an error occurs while loading the CSV file, EXTRARNAS can be started with the following JVM option: 

-Dcom.sun.xml.bind.v2.bytecode.ClassTailor.noOptimize=true

Current limitations

mmCIF-to-PDB conversion for bundled PDB entries may fail in a small number of cases because of placeholder crystallographic records produced by BeEM.
